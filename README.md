# designcourt

The decision layer and deterministic judge for AI design.

An agent without a decision layer guesses. An agent that guesses defaults to the average of its training data: purple gradients, glowing borders, Inter font, and three equal cards in a row.

`designcourt` gives your AI agent an explicit design decision before it writes a line of code, and an uncompromising deterministic audit after it renders.

---

## Proven benchmark results (reproducible)

We assume our tool is wrong until the labeled corpus proves otherwise. Below are the measured numbers across 48 labeled test pages (39 synthetic injected pairs, 8 curated real pages, and 1 historical regression page).

All numbers are measured on a real machine and can be regenerated by running `npm run bench`.

### Lane A: Artifact detectors (HTML and CSS audit)

Measured against the current market leader ([Impeccable](https://github.com/ibelick/impeccable), 61 rules, 68k stars) and the founder's previous gate baseline (`anti-slop-check.py`):

| Tool | Coverage | Precision | Recall | Macro F1 | Blocker escape rate | Runtime |
|---|---|---|---|---|---|---|
| **gate_baseline** (designkit v1) | 7 tells | 0.057 | 0.118 | 0.077 | **100.0%** (15/15 escaped) | 8.4s |
| **impeccable** (v4.1.0) | 5 tell mappings | **0.692** | 0.097 | 0.170 | **40.0%** (6/15 escaped) | 57.0s |
| **designcourt judge** (v0.1.0) | **38 tells** | 0.454 | **0.796** | **0.578** | **6.7%** (1/15 escaped) | **1.5s** |

#### Honest analysis of the numbers

1. **Where designcourt wins:**
   - **Escape rate**: drops blocker escape rate from 40% (Impeccable) and 100% (gate baseline) down to **6.7%**. The purple gradient that slipped past the old gate is caught with 100% precision.
   - **Recall**: 79.6% across 38 distinct AI tells, compared to 9.7% for Impeccable (which focuses on color and micro-contrast but misses layout and structural tells).
   - **Speed**: 1.5s vs 57.0s because designcourt has **zero dependencies** and parses deterministically without an AST bloat.

2. **Where designcourt lost or must improve:**
   - **Precision**: Impeccable achieved higher precision (0.692 vs 0.454) on the subset of color rules it implements. Designcourt emitted 89 false positives on secondary rules (e.g. strict hero discipline and font-family fallbacks).
   - **One blocker escaped**: in `dashboard-shell-slides.html`, a subtle multi-tier card nest escaped DC-201 because it used flexbox instead of CSS grid. We report this openly.

### Lane B: Spec validation

Measured against [`@google/design.md`](https://github.com/google-labs-code/design.md) (Apache-2.0):
- Google's tool validates DESIGN.md design system specifications (tokens, contrast, typography exports).
- Verified against `designkit/DESIGN.md`: **PASS** in 8.1s.
- Google solves the *specification* layer. `designcourt` solves the *execution and render* layer. They complement each other.

## The Regression This Product Closes

In `designkit`, `DESIGN.md:50` banned the "AI purple gradient". But `styles/layout.css:323` contained:
```css
radial-gradient(120% 120% at 100% 0%, var(--color-primary-soft) 0%, transparent 60%)
```
The old check script returned:
```
ANTI-SLOP: PASS (168 checks, 24 files, 0 failures)
```
The ban existed in prose, but was never mechanized. `designcourt judge` resolves variables through the token tree and reports:
```
[BLOCKER] DC-101 (purple-gradient): Purple, violet or indigo gradient
  Line 47: background: radial-gradient(120% 120% at 100% 0%, var(--color-primary-soft)... | stop #eef2ff
  Fix: Replace the purple stop with a neutral surface or the single declared accent.
```

## How it works: Decide, Build, Judge

Most agent UI workflows look like this:
> Prompt -> Model guesses -> Generic slop output

The designcourt loop:
> **1. The Ruling (`plan`)**: establish mode, constraints, dials, and non-repeating layout families before building.
> **2. The Build**: agent implements against the binding contract.
> **3. The Judge (`judge`)**: deterministic scanner checks the rendered code against 38 known tells.
> **4. Repair**: agent fixes any blocker or major finding until the verdict is `clean`.

## Quick Start

### 1. Installation

Zero runtime dependencies. Requires Node.js 18+.

```bash
npm install -g designcourt
```

### 2. Generate a design contract (The Ruling)

```bash
# By goal and mode
designcourt plan "Fleet dispatcher dashboard" --mode operate

# From a brief file
designcourt plan --file brief.md
```

### 3. Audit an HTML artifact (The Judge)

```bash
# Terminal summary (exit code 1 on fail, 0 on pass)
designcourt judge dist/index.html

# Full JSON output with line numbers and fixes
designcourt judge dist/index.html --json
```

### 4. Model Context Protocol (MCP) Server

Connect designcourt to Claude Code, Cursor, Windsurf, or Hermes Agent:

```json
{
  "mcpServers": {
    "designcourt": {
      "command": "node",
      "args": ["C:/Users/muzph/projetos/designcourt/src/cli.mjs", "mcp"]
    }
  }
}
```

Available tools in MCP:
- `designcourt_plan`: turns a prompt into an authoritative contract.
- `designcourt_judge`: scans an artifact and returns structured findings.
- `designcourt_decide`: queries the 23 verified design decisions.

## The Decision Library

The core contains 23 structured decisions in `decisions/`, across four operating modes:
- **persuade**: high expressiveness, single accent, asymmetric hero, proof grids.
- **operate**: compact scale, status palette, data tables, zero decorative color.
- **read**: classic book scale, 65ch measure, deep ink accents, reading typefaces.
- **experience**: atmospheric palette, narrative depth spine, reduced motion gates.

Each decision states when to use it, **when NOT to use it**, the trade-off accepted, and the specific failure mode it prevents.
